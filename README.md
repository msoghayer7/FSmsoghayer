# نظام الإدارة المالية (ERP/CRM) — العقود، المصروفات وفق الاستحقاق، والأصول الثابتة

نواة أولية قابلة للتشغيل لنظام شبيه بأنظمة ERP/CRM العالمية (SAP وما شابهها)، تركّز في هذه المرحلة على ثلاث وحدات:

1. **إدارة العقود** — دورة حياة كاملة (مسودة → نشط → مجدّد/مفسوخ)، مع ربط كل عقد بمورّد/عميل وحساب مصروف افتراضي.
2. **المصروفات وفق أساس الاستحقاق (Accrual Basis)** — تسجيل المصروف كأصل مقدّم (Prepaid) وتوزيعه بالقسط الثابت على أشهر الاستحقاق، مع قيد محاسبي مستقل لكل فترة.
3. **الأصول الثابتة** — سجل أصول، إهلاك بالقسط الثابت مولّد تلقائيًا، وقيود اقتناء/إهلاك/استبعاد مرحّلة لدفتر الأستاذ.

الأساس المشترك لكل ذلك هو **محرك قيود يومية مزدوجة القيد (Double-Entry GL Engine)**: أي أثر مالي في العقود أو المصروفات أو الأصول يمر عبر خدمة واحدة (`JournalEntriesService`) تتحقق أن مجموع المدين = مجموع الدائن قبل الترحيل، بحيث لا يمكن لأي وحدة أن "تكسر" ميزان الدفاتر.

## نموذج البيانات (ملخص)

### المحاسبة العامة (`accounting/`)
- **gl_accounts**: دليل الحسابات (شجرة حسابات) — كود، اسم، نوع (أصل/التزام/حقوق ملكية/إيراد/مصروف).
- **journal_entries** + **journal_entry_lines**: القيد اليومي وسطوره، بحالة DRAFT/POSTED ومصدر (عقد، مصروف استحقاق، اقتناء/إهلاك/استبعاد أصل، يدوي).

### العقود (`contracts/`)
- **contracts**: رقم العقد، الطرف الآخر، النوع، المدة، القيمة، تكرار الفوترة، حساب المصروف الافتراضي، الحالة.
- **contract_lines**: تفصيل بنود العقد (اختياري).

### المصروفات وفق الاستحقاق (`expenses/`)
- **expenses**: مصروف مرتبط اختياريًا بعقد، بطريقة اعتراف إما **فوري (IMMEDIATE)** أو **قسط ثابت (STRAIGHT_LINE)**.
- **expense_accrual_schedule**: جدول الفترات الشهرية الناتج تلقائيًا من تاريخي بداية/نهاية الاستحقاق، كل فترة تُرحّل بشكل مستقل.

**تدفق العمل المحاسبي:**
1. إنشاء المصروف (DRAFT) → يُحسب جدول الفترات تلقائيًا (توزيع المبلغ بالتساوي + تسوية فرق التقريب في آخر فترة).
2. الاعتماد (Approve):
   - **فوري**: قيد واحد `مدين: حساب المصروف / دائن: حساب الدائنين` ويُغلق المصروف مباشرة.
   - **قسط ثابت**: قيد `مدين: مصروفات مقدّمة (أصل) / دائن: حساب الدائنين` بكامل المبلغ، ثم يبقى المصروف بحالة APPROVED.
3. ترحيل كل فترة استحقاق على حدة (Recognize): قيد `مدين: حساب المصروف / دائن: مصروفات مقدّمة` بمبلغ الفترة فقط — وهذا هو جوهر "أساس الاستحقاق": الأصل المقدّم يتحول إلى مصروف فعلي شهرًا بعد شهر.

### الأصول الثابتة (`assets/`)
- **asset_categories**: فئة الأصل مع الحسابات الافتراضية (حساب الأصل، حساب مصروف الإهلاك، حساب مجمع الإهلاك) والعمر الإنتاجي الافتراضي.
- **fixed_assets**: الأصل الفعلي (تكلفة، قيمة خردة، عمر إنتاجي، حالة).
- **asset_depreciation_schedule**: جدول إهلاك بالقسط الثابت يُنشأ تلقائيًا عند إضافة الأصل.

**تدفق العمل المحاسبي:**
1. إنشاء الأصل → توليد جدول إهلاك كامل لكل أشهر العمر الإنتاجي.
2. ترحيل قيد الاقتناء: `مدين: حساب الأصل / دائن: حساب الدائنين` (شرط لازم قبل بدء الإهلاك).
3. ترحيل كل فترة إهلاك: `مدين: مصروف الإهلاك / دائن: مجمع الإهلاك`.
4. الاستبعاد (Dispose): قيد واحد متوازن تلقائيًا يعكس مجمع الإهلاك، يثبت المتحصلات النقدية، ويحسب **الربح أو الخسارة** الناتجة عن الاستبعاد مقارنة بالقيمة الدفترية.

## التشغيل محليًا

### 1. قاعدة البيانات
```bash
docker compose up -d
# أو استخدم أي PostgreSQL 16 محلي وحدّث backend/.env تبعًا لذلك
```

### 2. الخلفية (Backend)
```bash
cd backend
cp .env.example .env
npm install
npm run seed     # ينشئ دليل الحسابات + مستخدم admin@fsm-erp.local / Admin@12345 + بيانات تجريبية
npm run start:dev
# API على http://localhost:3000/api
```

### 3. الواجهة (Frontend)
```bash
cd frontend
cp .env.example .env
npm install
npm run dev
# الواجهة على http://localhost:5173
```

سجّل الدخول بـ `admin@fsm-erp.local` / `Admin@12345`.

## ملاحظات مهمة قبل الإنتاج

- `synchronize: true` في TypeORM مفعّل للتسهيل في هذه المرحلة الأولية؛ يجب استبداله بـ **migrations** حقيقية قبل أي بيئة إنتاج.
- أرقام المستندات (العقود/المصروفات/الأصول/القيود) تُولَّد حاليًا بطابع زمني بسيط لضمان عدم التكرار دون الحاجة لتسلسل قاعدة بيانات؛ يُنصح باستبدالها بتسلسل (sequence) حقيقي عند التوسع.
- الصلاحيات مبنية على الأدوار (`UserRole`: ADMIN, FINANCE_MANAGER, ACCOUNTANT, PROCUREMENT, VIEWER) لكنها مفعّلة حاليًا فقط على وحدة المستخدمين كمثال؛ يمكن تعميمها على بقية الوحدات بإضافة `@Roles(...)` على المسارات المطلوبة.

## الخطوات التالية المقترحة

- وحدة **CRM** (العملاء، الفرص البيعية، المتابعة) — تم تأجيلها في هذه المرحلة حسب الأولوية المتفق عليها.
- تقارير مالية جاهزة (ميزان المراجعة، قائمة الدخل) مبنية على `journal_entries`.
- تنبيهات انتهاء/تجديد العقود، ومرفقات العقود.
- ربط تلقائي بين تكرار فوترة العقد وتوليد مصروفات دورية دون تدخل يدوي.
