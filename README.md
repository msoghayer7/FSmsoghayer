# نظام الإدارة المالية (ERP/CRM) — العقود، المصروفات وفق الاستحقاق، والأصول الثابتة

نواة قابلة للتشغيل لنظام مالي حكومي مبني على **دليل الحساب الحكومي الموحد** الرسمي للمملكة العربية السعودية ومعايير **IPSAS**، تركّز في هذه المرحلة على ثلاث وحدات:

1. **إدارة العقود** — دورة حياة كاملة (مسودة → نشط → مجدّد/مفسوخ)، مع ربط كل عقد بمورّد/عميل وحساب مصروف افتراضي.
2. **المصروفات وفق أساس الاستحقاق (Accrual Basis)** — تسجيل المصروف كأصل مقدّم (Prepaid) وتوزيعه بالقسط الثابت على أشهر الاستحقاق، مع قيد محاسبي مستقل لكل فترة.
3. **الأصول الثابتة** — سجل أصول، إهلاك بالقسط الثابت مولّد تلقائيًا، وقيود اقتناء/إهلاك/استبعاد مرحّلة لدفتر الأستاذ.

الأساس المشترك لكل ذلك هو **محرك قيود يومية مزدوجة القيد (Double-Entry GL Engine)**: أي أثر مالي في العقود أو المصروفات أو الأصول يمر عبر خدمة واحدة (`JournalEntriesService`) تتحقق أن مجموع المدين = مجموع الدائن، وتُنشئ القيد دائمًا بحالة **مسودة (Draft)** — لا يصبح نافذًا في الدفاتر إلا بعد **اعتماد صاحب الصلاحية** صراحة، عندها فقط تُحدَّث حالة المصروف/الأصل المرتبط تلقائيًا (عبر أحداث داخلية) لتعكس الترحيل الفعلي.

## البنية التقنية

| الطبقة | التقنية |
|---|---|
| الخلفية (Backend) | NestJS + TypeORM + PostgreSQL + JWT Auth + Event Emitter |
| الواجهة (Frontend) | React + TypeScript + Vite (واجهة عربية بالكامل، RTL، أرقام إنجليزية موحّدة) |
| قاعدة البيانات | PostgreSQL 16 |

```
FSmsoghayer/
├── backend/     # NestJS API — كل الوحدات والمنطق المحاسبي
│   └── src/database/seeds/data/chart-of-accounts.json   # دليل الحساب الحكومي الموحد كاملاً (2,589 حسابًا)
├── frontend/    # React SPA — تسجيل دخول + لوحة تحكم + شاشات كل وحدة
└── docker-compose.yml   # تشغيل PostgreSQL محليًا
```

## نموذج البيانات (ملخص)

### المحاسبة العامة (`accounting/`)
- **gl_accounts**: دليل الحساب الحكومي الموحد الكامل — كود (حتى 9 خانات)، اسم، **المستوى (1-7)**، الحساب الأب، النوع، طبيعة الرصيد (مدين/دائن/مختلط)، **تفصيلي أو تجميعي** (`isPostable`)، **مفعّل/موقوف** (`isActive`)، ومسار الأسلاف (`path`) لتسريع تجميع التقارير حسب المستوى.
- **journal_entries** + **journal_entry_lines**: القيد اليومي وسطوره، بحالة **DRAFT (مسودة) → POSTED (مرحّل)** فقط بعد اعتماد صريح، ومصدر (عقد، مصروف مبدئي/استحقاق، اقتناء/إهلاك/استبعاد أصل، يدوي).

### العقود (`contracts/`)
- **contracts**: رقم العقد، الطرف الآخر، النوع، المدة، القيمة، تكرار الفوترة، حساب المصروف الافتراضي، الحالة.
- **contract_lines**: تفصيل بنود العقد (اختياري).

### المصروفات وفق الاستحقاق (`expenses/`)
- **expenses**: مصروف مرتبط اختياريًا بعقد، بطريقة اعتراف إما **فوري (IMMEDIATE)** أو **قسط ثابت (STRAIGHT_LINE)**.
- **expense_accrual_schedule**: جدول الفترات الشهرية الناتج تلقائيًا من تاريخي بداية/نهاية الاستحقاق، بحالة PENDING → **AWAITING_APPROVAL** (بعد إنشاء القيد كمسودة) → POSTED (بعد اعتماد القيد).

**تدفق العمل المحاسبي:**
1. إنشاء المصروف (DRAFT) → يُحسب جدول الفترات تلقائيًا (توزيع المبلغ بالتساوي + تسوية فرق التقريب في آخر فترة).
2. الاعتماد (Approve) — ينشئ قيدًا **كمسودة**:
   - **فوري**: `مدين: حساب المصروف / دائن: حساب الدائنين`.
   - **قسط ثابت**: `مدين: مصروفات مقدّمة (أصل) / دائن: حساب الدائنين` بكامل المبلغ.
3. بعد اعتماد هذا القيد من شاشة **القيود اليومية**، يتحول المصروف تلقائيًا لحالة APPROVED/POSTED.
4. ترحيل كل فترة استحقاق (Recognize) — يتطلب أن يكون القيد المبدئي **معتمدًا** أولاً — ينشئ قيدًا آخر كمسودة: `مدين: حساب المصروف / دائن: مصروفات مقدّمة` بمبلغ الفترة، يتحول لـ POSTED بعد اعتماده.

### الأصول الثابتة (`assets/`)
- **asset_categories**: فئة الأصل مع الحسابات الافتراضية (حساب الأصل، حساب مصروف الإهلاك، حساب مجمع الإهلاك) والعمر الإنتاجي الافتراضي.
- **fixed_assets**: الأصل الفعلي (تكلفة، قيمة خردة، عمر إنتاجي، حالة).
- **asset_depreciation_schedule**: جدول إهلاك بالقسط الثابت يُنشأ تلقائيًا عند إضافة الأصل.

**تدفق العمل المحاسبي:** (كل قيد يُنشأ كمسودة ويتطلب اعتمادًا منفصلاً من شاشة القيود، تمامًا كالمصروفات)
1. إنشاء الأصل → توليد جدول إهلاك كامل لكل أشهر العمر الإنتاجي.
2. قيد الاقتناء: `مدين: حساب الأصل / دائن: حساب الدائنين` (يجب أن يكون **معتمدًا** قبل بدء الإهلاك).
3. قيد كل فترة إهلاك: `مدين: مصروف الإهلاك / دائن: مجمع الإهلاك`.
4. الاستبعاد (Dispose): قيد واحد متوازن تلقائيًا يعكس مجمع الإهلاك، يثبت المتحصلات النقدية، ويحسب **الربح أو الخسارة** على حساب واحد مزدوج الطبيعة (مطابقًا لحساب "مكاسب أو خسائر متحققة من بيع الأصول الملموسة" في الدليل الحكومي).

## الشاشات المتاحة

- **لوحة التحكم**: ملخص عام + آخر القيود.
- **العقود / المصروفات / الأصول الثابتة**: قوائم، نماذج إنشاء، وتفاصيل مع إجراءات الاعتماد والترحيل.
- **دليل الحسابات**: بحث، عرض المستوى، تفعيل/إيقاف كل حساب.
- **القيود اليومية**: تبويب مسودات/مرحّلة، تفاصيل كل قيد، **اعتماد** (لمن يملك صلاحية ADMIN أو FINANCE_MANAGER).
- **ميزان المراجعة**: تجميع حسب أي مستوى (1-7)، مع خيار إخفاء الحسابات ذات الرصيد الصفري.
- **المعلومات العامة**: بيانات الجهة، السنة المالية، العملة.

## التشغيل محليًا

### 1. قاعدة البيانات
```bash
docker compose up -d
# أو استخدم أي PostgreSQL 16 محلي وحدّث backend/.env تبعًا لذلك
```

### 2. الخلفية (Backend)
```bash
cd backend
cp .env.example .env
npm install
npm run seed     # يستورد دليل الحسابات كاملاً + مستخدم admin@fsm-erp.local / Admin@12345 + بيانات تجريبية
npm run start:dev
# API على http://localhost:3000/api
```

### 3. الواجهة (Frontend)
```bash
cd frontend
cp .env.example .env
npm install
npm run dev
# الواجهة على http://localhost:5173
```

سجّل الدخول بـ `admin@fsm-erp.local` / `Admin@12345`.

## ملاحظات مهمة قبل الإنتاج

- `synchronize: true` في TypeORM مفعّل للتسهيل في هذه المرحلة الأولية؛ يجب استبداله بـ **migrations** حقيقية قبل أي بيئة إنتاج.
- أرقام المستندات (العقود/المصروفات/الأصول/القيود) تُولَّد حاليًا بطابع زمني بسيط لضمان عدم التكرار دون الحاجة لتسلسل قاعدة بيانات؛ يُنصح باستبدالها بتسلسل (sequence) حقيقي عند التوسع.
- الصلاحيات مبنية على الأدوار (`UserRole`: ADMIN, FINANCE_MANAGER, ACCOUNTANT, PROCUREMENT, VIEWER)، ومُفعّلة على اعتماد القيود وتفعيل/إيقاف الحسابات وتعديل المعلومات العامة؛ يمكن تعميمها على بقية المسارات بإضافة `@Roles(...)`.
- لا يوجد حاليًا مركز تكلفة على مستوى سطر القيد (حُذف بناءً على تأكيد عدم استخدامه)؛ مقطع "مراكز التكلفة" في الدليل الحكومي موجود في ملف البيانات المصدري لكنه غير مُفعّل في النموذج.

## الخطوات التالية المخطط لها (المرحلة الثانية)

- **شاشة المطابقات** (بنكي، دائنين/مدينين، بين الجهات) استنادًا لنماذج دليل تجميع البيانات وتوحيد القوائم المالية.
- **وحدة تقارير مخصّصة** قابلة للتصدير Excel/PDF.
- **رفع القيود اليومية من ملف Excel** (تُنشأ كمسودات بانتظار الاعتماد).
- **مكتبة مرجعية** لدليل السياسات المحاسبية ودليل الإجراءات ودليل المعايير (IPSAS) داخل النظام.
- وحدة **CRM** (العملاء، الفرص البيعية، المتابعة) — مؤجّلة حسب الأولوية المتفق عليها.
